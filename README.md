# CLIProxyAPI Usage Keeper

CLIProxyAPI 的轻量级用量记录与分析插件。插件接收 CLIProxyAPI 已完成的 `UsageRecord`，通过内存队列异步写入 SQLite，并提供概览、接口统计、请求明细、价格管理和数据备份功能。

## 功能

- 用量趋势：请求数、输入/输出 Token、缓存 Token、缓存命中率和费用；支持 24 小时、7 天、30 天、全部与自定义起止时间（中国标准时间）。自定义范围使用双月日历，仅有请求明细的日期可选；起止时刻可精确到秒。
- 运行状态：队列深度、写入数量、失败数量、数据库记录数和保留策略。
- 分析视图：按模型、Provider、客户端 Key 和来源查看请求分布。
- 请求明细：按时间、Provider、模型、状态和关键字筛选，并支持 CSV 导出。
- 上游详情：查看指定上游的模型分布、汇总指标和最近请求。
- 价格管理：按模型配置输入、输出、缓存读取、缓存写入和推理价格。
- 数据管理：导出和恢复完整备份，恢复前会校验备份完整性；超过导出上限时明确报错，不会下载不可恢复的截断文件。
- 隐私保护：管理页面只显示脱敏后的客户端 Key、Provider 凭证和来源名称。
- 错误正文与请求地址脱敏：邮箱沿用首尾掩码，常见认证头、命名密钥、`sk-` 密钥和 JWT 隐藏为 `***`；地址移除用户信息、查询参数和片段，并清洗路径中的敏感值。
- 主题支持：支持浅色、深色主题，以及移动端布局和键盘操作。

## 设计边界

- 只声明 `usage_plugin` 和 `management_api` 能力。
- 不启动独立 HTTP 服务，不轮询 CLIProxyAPI，也不依赖 Redis。
- `usage.handle` 只负责 JSON 解码、脱敏和非阻塞入队，不执行磁盘 I/O。
- SQLite 使用 WAL、短事务和分钟级汇总表；明细查询使用毫秒级时间边界。
- 统计接口返回的客户端 Key 为匿名标识，可直接用于明细和 CSV 筛选。
- 脱敏覆盖新事件入库、管理查询、CSV 导出、备份导出与导入；历史事件在读取和导出时再次清洗。不会自动改写已有数据库、WAL 文件或此前导出的备份，需按原始敏感数据保管这些文件。
- 自由文本脱敏针对可识别的邮箱与凭证格式，无法保证识别所有自定义敏感内容。正常错误原因、状态码和普通接口路径保留；无法解析的地址隐藏，超过 16 KiB 的错误正文或地址整体隐藏，最终输出仍限制为 512/256 字节。

## 写入与查询边界

- 批写失败后保留当前批次，最多尝试 3 次，重试前分别等待 250 ms、500 ms。仅重试可以确认尚未提交的批次；提交或回滚结果不确定时停止重放，避免重复累计事件和 Rollup。
- `write_failures` 统计失败尝试次数；`write_dropped` 统计重试耗尽后确认丢弃的事件数；`write_uncertain` 单独统计写入结果无法确认的事件数。`dropped` 包含无效事件、入队失败及 `write_dropped`，不包含 `write_uncertain`；`written` 只统计确认提交成功的事件。这些计数在插件运行期间累计，重启后重置。
- 入队仍然非阻塞。内存队列不具备持久性，持续存储故障、队列满或进程崩溃仍可能丢失记录；正常关闭会处理队列和不足一批的剩余事件，包括有限重试。
- 恢复备份前，写入协程会刷完此前已入队的事件并暂停；恢复结束后（包括失败时）再写入新事件。恢复期间新事件继续进入有界队列，队列满时计入现有 `dropped` 指标。
- 备份导出前也会等待一次写入屏障，确保调用前已入队的事件先完成刷盘；随后恢复正常写入，再读取 SQLite 快照。
- 关闭磁盘存储时，内存数据库持有一条专用保活连接，避免丢弃异常写连接时连带清空已有记录；插件关闭时释放该连接，内存数据不跨重启保留。
- `/events` 每页最多 200 条，`page` 最大为 40,001，同时要求 `OFFSET = (page - 1) × page_size` 不超过 1,000,000。校验在乘法前完成，越界返回 HTTP 400。例如每页 25 条最多请求第 40,001 页，每页 200 条最多请求第 5,001 页。需要更早的记录时请缩小时间范围。
- 分页响应的 `pages` 表示实际总页数，`accessible_pages` 表示上述限制内可访问的页数，页面据此停止继续翻页。合法页码超过实际总页数时返回空数组。
- `/summary` 的存储信息来自实际采样：事件数、Rollup 数、SQLite 日志模式，以及数据库文件与 WAL 文件的合计大小。内存模式没有磁盘文件，大小为 0、日志模式为 `memory`。采样结果缓存 5 秒；设置查询强制重新采样，清理和恢复成功后使存储快照失效。
- `sampled_at` 标明采样时间。采集失败时，有历史快照则保留旧值并设置 `metrics_stale`；没有成功快照时 `metrics_available=false`，计数和大小为 `null`，页面显示“未知”。`metrics_error` 给出采集错误。管理响应另有 4 秒缓存，前端缓存和自动刷新间隔为 60 秒，因此页面不是实时读数。
- CSV 导出会检查所有文本列的首个有效字符；忽略前导空白、控制字符和 Unicode 格式字符后，以 `= + - @` 开头的单元格添加单引号前缀，降低被表格软件解释为公式的风险。数值列和数据库原值不变，逗号、引号、换行仍由标准 CSV 编码处理；此保护针对本次导出，不保证其他软件重新保存后的内容仍受保护。
- CSV 筛选结果超过 `export_max_records` 时返回 HTTP 409 `csv_limit_exceeded`，不会下载不完整的文件；可提高上限或缩小筛选范围后重试。
- 完整备份超过 `export_max_records` 时 `/backup` 返回 HTTP 409 `backup_limit_exceeded`，前端显示原因；可调高上限（最高 1,000,000 条）后重试。历史格式中的 `truncated: true` 仍会在恢复时被拒绝。

## 构建要求

插件使用 CGO 构建：

- Windows：MinGW-w64
- Linux：`gcc` 或 `musl-gcc`
- macOS：Xcode Command Line Tools

需要 Go 1.24 或更高版本。

## 构建

在仓库根目录运行：

```powershell
.\scripts\build.ps1 -Version 1.6.6
```

指定目标平台：

```powershell
.\scripts\build.ps1 -Version 1.6.6 -GoOS windows -GoArch amd64
```

构建产物位于 `release/`，脚本会同时生成压缩包和 SHA-256 校验文件。

## 测试

```powershell
cd go
go test ./...
go vet ./...
node --check dashboard/app.js
node dashboard/app_test.cjs
```

Node 回归测试会调用 Go 测试生成真实 API JSON，检查上游详情的 `ttft_ms` 字段、TTFT/TPS 显示、分页限制和存储快照渲染；需要同时安装 Go 和 Node.js。

## 配置

可参考 [config.example.yaml](config.example.yaml)。常用设置包括：

- `retention_days`：明细保留天数。
- `batch_size`：批量写入数量。
- `flush_interval_ms`：定时刷新间隔。
- `export_max_records`：备份和 CSV 导出的最大记录数。

配置更新与后台清理使用同一把锁，修改保留天数后不会继续使用旧值执行清理。

## 发布

插件当前版本为 **1.6.6**。更新 `registry.json` 中的版本号并推送到 `main` 后，GitHub Actions 自动创建对应的 `vMAJOR.MINOR.PATCH` 标签，并构建各平台压缩包和校验文件；已发布的版本会跳过，发布失败时可复用已有标签重试。
